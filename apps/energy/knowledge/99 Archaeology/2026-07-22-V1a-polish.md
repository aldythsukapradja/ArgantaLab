# V1a Polish — Real WebGL 3D + Full Interactivity

Executed against the LOCKED spec `docs/arganta-energy/V1A-POLISH-SPEC.md`. Founder
mandate: "visual and interactivity is the key — premium wow effect. No static SVG
for data. Real 3D." Standing operating principle for ArgantaEnergy.

## What changed

### 1 · Map 3D → REAL WebGL (`Map3D.tsx`, new, lazy)
- Replaced the isometric painter's-algorithm canvas branch with a real
  react-three-fiber `<Canvas>`, **code-split via `lazy(() => import('./Map3D'))`**
  so `three` never enters the base bundle.
- Surface `BufferGeometry` deformed by TVDSS from the active grid; null cells skip
  triangles (real holes); `computeVertexNormals` for smooth lighting; per-vertex
  depth colors from the token `depthRamp()` (both themes).
- OrbitControls (orbit / pan / zoom-to-cursor / damping), hemisphere + ambient +
  2× directional lights. Vertical-exaggeration ×1–20 (shared with inspector slider).
- Stackable secondary horizons (Hugin Top/Base/BCU) loaded lazily, per-surface
  opacity; wells as 3D `TubeGeometry` from trajectories colored by role with drei
  `<Billboard>`+`<Html>` labels; planned scenario wells as cones + labels.
- On-canvas cluster: reset / top view (imperative `CameraRig`), wireframe,
  auto-orbit (disabled under reduced-motion), stack toggles + opacity. Hover-cell
  readout. Badge honestly relabelled **"3D · WebGL"**.
- `frameloop="demand"` (renders only on change / interaction) → premium perf,
  reduced-motion friendly. The 2D structural map is untouched.

### 2 · X-Section → fully interactive (`XSection.tsx`, rewrite)
- Was ZERO handlers. Now: wheel zoom-to-cursor on **both** distance + depth axes,
  drag-pan, dblclick-fit, hover crosshair readout (distance / TVD / sampled horizon
  depths / fluid zone gas-oil-water), draggable A–A′ endpoints that re-sample the
  section live (`onUpdateLine` back into MapView shapes), flatten-on-surface datum,
  vertical-exag slider, gradient fluid fills clipped by OWC, hung wells + pick ties.

### 3 · Correlation → fully interactive (`CorrelationView.tsx`, rewrite)
- Was chip-reorder only. Now: synchronized depth zoom-to-cursor (wheel) + pan across
  all wells, hover crosshair with per-well GR readouts, **drag-to-reorder columns on
  the panel** (drag header), **per-well depth-shift by dragging a column body**,
  animated flatten-on-marker (easeOutCubic, reduced-motion instant), hover-surface
  highlights its correlation line across every well (glow).

### 4 · Analytics overlap fixed + premium (`LogsView.tsx`, `Crossplot.tsx`,
`Crossplot3D.tsx` new)
- Root bug: the 380 px in-flow Crossplot drawer collided with the 296 px in-flow
  inspector `aside`. Fix: Analytics is now a **full-width resizable bottom dock**
  inside the left column (drag handle, 120–640 px) — the inspector is a separate
  flex sibling, so they can never overlap at any width incl. mobile (verified: no
  horizontal scroll at 390 px).
- Crossplot 2D: added density **hexbin** toggle, GR color-ramp legend, nearest-point
  hover readout; kept lasso/box → interval highlight + clear.
- Crossplot 3D is now a **real r3f WebGL point cloud** (lazy `Crossplot3D.tsx`,
  OrbitControls) with labelled GR/RHOB/NPHI axes — replaced the orthographic canvas.

## Gotchas
- **r3f initial-measure lag:** when a `<Canvas>` mounts into a just-revealed
  (Suspense→content) absolute box, the first react-use-measure can return the drei
  default 300×150. Fix: `requestAnimationFrame(() => window.dispatchEvent(new Event('resize')))`
  on mount. Same pattern nudges the Logs track canvas when the Analytics dock toggles
  (the `useCanvas` ResizeObserver otherwise lagged, letting the fixed-px canvas
  overflow the dock); also added `overflow:hidden` to the tracks wrap as a guard.
- **Screenshot capture wedges while a WebGL canvas is actively rendering** (orbit
  damping / theme reflow). Browser-pane artifact — verify via DOM/JS/console during
  active render, capture stills after settle. `frameloop="demand"` mitigates.
- **Stale-viewport squish:** the app measures window size; after a browser resize you
  must reload for the workbench to fill — not a code bug.
