## GAP 2 — LAS 3.0 pressure logs

- New decoder `decode-las3.py` — hand-rolled LAS 3.0 section parser (no lasio/
  welly, which hung). Reads `~Version` for VERS/WRAP/`DLM`, NULL from the Well
  block, pairs `~*_Definition` ↔ `~*_data` (via the `| <definition>` reference in
  the data header), parses with the DECLARED delimiter only.
- **48 of 48 LAS 3.0 pressure runs decoded, 0 deferred.** All time-indexed
  (first curve TIME.S), ~58 curves each (FPWD/pretest MWD channels: DEPTH,
  quartz/strain gauge pressures in BAR, temps in DEGC…). NULL `-999.25` → null.
  72 LAS 2.0 pressure files in the same folders correctly skipped (main decoder).
- Output `processed/pressure/<well>__<run>.json` (downsampled preview inline) +
  `processed/pressure/full/<well>__<run>.json` for runs > 800 rows.
- well_id null for all 48 (same F-well master-naming mismatch as GAP 1); source_well
  carried verbatim. dataNature `measured`; no unit conversion.
- Key parser gotcha: in LAS header/param lines the VALUE lives in the DATA field
  (before the colon), not after it — VERS/NULL/DLM would mis-read if you take the
  post-colon description. `parse_meta_line` splits unit (attached to the dot) from
  value (rest before colon) from description (after colon).
