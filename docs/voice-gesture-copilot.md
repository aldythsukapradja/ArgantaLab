# Voice + Gesture Copilot — HQ Landing

Status: **implemented** (v2). Deterministic voice commands + swipe/pinch
gesture on the `apps/hq` Landing surface, now with a live listening HUD,
command-flash overlay, a DB-backed command registry, a cheat-sheet popup, and
spoken replies via Cloudflare Aura. No LLM at runtime, no cloud STT.

## v2 additions (this pass)

- **Listening HUD** (`CopilotHUD.tsx`) — a glass panel above the mic while
  armed/gesturing: live waveform (mic amplitude), **interim transcript** as
  you speak (`interimResults` on), the matched command with a ✓, gesture
  state (loading / hand-seen / last-swipe arrow), and a reply mute toggle.
- **Command flash** (`CommandFlash.tsx`) — a premium iris-wipe + label sweep
  when a navigation/product command fires (~700ms, skipped for
  stop/help/wake and under reduced motion).
- **Command registry DB** (`registry.ts` + `supabase/migration_voice_commands.sql`)
  — commands live in `hq_voice_command` (public read, operator write). The
  hardcoded `SEED_ROWS` in `intents.ts` is the offline fallback. Add/remove a
  command = a row insert, no deploy. `action_kind` is a **closed enum mapped
  to real functions** — a row can only remap to an action the app already
  exposes, never inject behaviour.
- **Cheat-sheet popup** (`CopilotHelp.tsx`) — renders the live registry
  grouped by category + gesture legend. Opens from the topbar `?`, the voice
  phrase "help" / "what can I say", and auto-shows on first-ever arm
  (localStorage `cp-help-seen`).
- **Spoken replies** (`reply.ts` + `generateReplies.ts`) — each command has a
  `reply_text`. "Browser instant, Aura on top": browser SpeechSynthesis speaks
  immediately; if a cached Cloudflare-Aura mp3 exists (generated by the
  operator "Generate voice replies" pass → `media-proxy` Aura-1 →
  `voice-replies` bucket), that plays instead. While a reply plays, phrase
  matching is gated (~duration) so Jarvis can't hear himself.

## v3 — global copilot (P1, SHIPPED + verified)

The copilot used to live inside `Landing.tsx`, which only mounts on
`surface === 'home'` — so it died the moment a command navigated away. It is
now **global**: `<GlobalCopilot>` is mounted once in `Shell` (outside the
surface switch) and survives every navigation, floating above popups.

**Architecture:**
- `copilot/store.ts` (`useCopilotStore`, Zustand) — the app-wide bridge.
  `GlobalCopilot` syncs reactive state (`armed`, `amplitude`, `gestureActive`,
  `gestureLoading`, `muted`) and registers imperative handles (`toggleVoice`,
  `toggleGesture`, `toggleMute`, `openHelp`). Any surface reads/drives it.
- `copilot/GlobalCopilot.tsx` — owns `useVoice`/`useGesture`, composes the
  effective `CopilotActions` (global base + the active surface's contextual
  overrides), renders the persistent `CopilotDock` (bottom-left), `CopilotHUD`
  (bottom-left, `corner="left"`), `CommandFlash`, and the cheat-sheet.
- `copilot/CopilotDock.tsx` — the always-visible bottom-left control (mic +
  gesture + help). Hidden only on the immersive orb `home` (Landing shows its
  own centre mic) and while `suppressed` (cinema/boot takeover). `z-index 210`,
  above popups.
- **Contextual bridge:** the active surface injects local actions via
  `setContext({ actions, onSwipe })`. Landing injects its product-popup /
  cinema / swipe behaviour. Off that surface, `openProduct`/`playCinema` route
  through the **pending bridge** (`requestProduct`/`requestCinema` → navigate
  home → Landing's `consumePending()` applies it), so "open lashira" works
  from anywhere.
- Landing no longer calls `useVoice`/`useGesture`; its dock mic and topbar
  buttons delegate to the store, and the orb reads `armed`/`amplitude` from it.

### Frozen seam contract (P2–P4 build against this — do not reshape)
1. `useCopilotStore` shape (state + handles + `context`/pending bridge) — the
   control tab (P3) calls a `reload()`-style refresh after edits; add that
   method here, don't fork the store.
2. `ActionKind` enum + `actionFor()` in `intents.ts` — P2 extends this with
   `setCommandTab` / `setDataTab` / `setBuilderSub` / `setProductView` /
   `goHome`; P3's action-picker renders the enum. Data-only, never code.
3. Global mount point is `<GlobalCopilot>` in `Shell` — P4's gesture-tuning
   panel and P3's editor read/write the same store; no new plumbing.
4. Registry write path targets the same `hq_voice_command` table the loader
   reads; edits go live via a store reload, no schema change.

**P3 — Copilot control tab.** New `copilot` surface (Rail → Command group).

**P4 — Gesture tuning.** `GestureSettings` (swipe/pinch enable, thresholds,

a ref so tuning applies without restarting the camera. Deliberately does
**not** offer gesture→arbitrary-action remapping — there are only two real
gestures (swipe, pinch), so the panel tunes their sensitivity/timing, not a
fake mapping table. Reset-to-defaults verified; persistence verified.

**Regression caught during this pass:** `GlobalCopilot` mounts as a
Shell-level sibling (outside `.ld`), so the HUD/flash/help/dock's `var(--ld-*)`
CSS tokens resolved to nothing everywhere — including on Landing itself,
since even there `GlobalCopilot` isn't nested inside `.ld`. Fixed by adding a
`:root`-scoped `--cp-*` token chain in `copilot.css` (`var(--ld-cyan,
#45e8ff)` etc.) that inherits `--ld-*` when in scope and falls back to a
fixed dark palette everywhere else. Verified via computed-style checks
post-fix.

## Scope (locked)

- **Voice**: the existing bottom-dock mic button (`.ld-mic`,
  [Landing.tsx:423](../apps/hq/src/surfaces/Landing.tsx)) becomes the voice
  trigger. A fixed phrase → action table. No conversation, no free-form
  intent parsing, no LLM call.
- **Orb**: reacts to voice only — pulses while listening, driven by live mic
  amplitude. It does **not** react to gesture. No explosion/rotation control
  via hands.
- **Gesture** is context-aware:
  - No popup open → swipe left/right cycles the 5 product cards (`selected`
    state in Landing).
  - A product popup open → swipe left/right cycles the inspector view
    (Overview → Desktop → Mobile, `InspectorView`), instead of switching
    products.
  - Pinch (thumb+index close) → closes whatever's open, same priority as the
    "close" voice command.
  - Camera access is opt-in via a separate toggle, off by default.

## Why Sonnet, not Opus

The difficulty here is browser-API lifecycle discipline (auto-restart,
cleanup, permission failure paths), not reasoning. Opus buys nothing; a
disciplined checklist does the work. See guardrails below — they are the
actual spec, not the phrase list.

## Architecture

```
apps/hq/src/copilot/
  intents.ts        # PURE: phrase → Intent table + runIntent(intent, hq). Unit-testable.
  useVoice.ts        # SpeechRecognition adapter → emits Intent + live amplitude (0..1)
  useGesture.ts      # HandLandmarker adapter → swipe → onSwipe('left'|'right')
apps/hq/public/mediapipe/
  hand_landmarker.task   # self-hosted model (no CDN fetch at runtime)
  wasm/                  # self-hosted MediaPipe WASM runtime
```

No new surface, no new store. `intents.ts` calls the existing `useHQ()`
actions directly (`go`, `openPalette`, `toggleTheme`, `toggleAgent`).

### Mic ownership

`SpeechRecognition` is single-instance. The copilot owns it; the phrase
"jarvis" / "hey arganta" calls the *existing* `toggleAgent()` rather than
sharing a recognizer with the agent orb. No tug-of-war between two mic
consumers.

### Orb reaction — reuses an existing seam, zero new reactor code

`CoreState` already has a `'listening'` state
([contract.ts:34](../apps/hq/src/reactor/contract.ts)) with its own
choreography entry (flat/idle framing — no explosion, matching "orb only
animates, doesn't restructure"). The only reactor change needed is a
one-line extension in `CoreR3F.tsx`'s `Rig`: the breathing-pulse trigger
currently checks `scene.speaker !== null` — extend it to also fire on
`scene.state === 'listening'`, then feed `scene.intensity` from a live
`AnalyserNode` reading on the mic stream while armed. Everything else
(pulse envelope, bloom, exposure) is existing code.

Landing.tsx branches its `reactorScene` computation only for `cinemaOn`
today ([Landing.tsx:348](../apps/hq/src/surfaces/Landing.tsx)); voice adds a
second branch — while listening, emit `{ ...IDLE_SCENE, state: 'listening',
intensity: liveAmplitude, signal: signalState }` instead of the legacy-prop
scene.

### Gesture → product swipe / inspector view / pinch-close

Swipe maps onto the existing `openProduct(id)` / `selected` state at
[Landing.tsx:296](../apps/hq/src/surfaces/Landing.tsx) — cycles through
`products`, same as clicking a product card. No reactor involvement.

When a product popup is open, `ProductDetail` accepts a controlled `view` +
`onViewChange` pair ([Portfolio.tsx:619](../apps/hq/src/surfaces/Portfolio.tsx))
— the same seam the Cinema Director already uses to drive
Overview/Desktop/Mobile during the cinematic. Landing lifts `productView`
state and swipe cycles it through `INSPECTOR_VIEWS` when `selected` is set,
falling back to product-cycling otherwise. One `onSwipe` callback, branching
on whether a popup is open — no separate gesture mode toggle needed.

Pinch detection is scale-invariant: `dist(thumbTip, indexTip) /
dist(wrist, middleMcp)` below a ratio threshold counts as a pinch, so it
fires the same regardless of how close the hand is to the camera. It maps to
the same `close()` action as the "close" voice command
([useGesture.ts](../apps/hq/src/copilot/useGesture.ts)).

## Intent table (v1)

Deterministic substring match against the final speech-recognition
transcript (lowercased, punctuation stripped). Each phrase has 2–3 aliases.

| Phrases | Action |
|---|---|
| "hey arganta", "hey jarvis" | `toggleAgent()` |
| "open portfolio" | `go('portfolio')` |
| "open growth", "open analytics" | `go('growth')` |
| "open command" | `go('command')` |
| "open build", "open game builder" | `go('game')` |
| "open media", "open media center" | `go('media')` |
| "open vault" | `go('vault')` |
| "open menu", "search" | `openPalette()` |
| "dark mode", "light mode", "switch theme" | `toggleTheme()` |
| "refresh", "refresh signals" | `refresh()` (passed in) |
| "activate" | `playCinema()` — starts the reactor cinematic |
| "close", "close this", "close it", "go back" | `close()` — smart close: cinema → product popup → agent panel → command palette, in that priority order, no-op if nothing's open |
| "open lashira", "open lashirabloom" | `openProduct('lashira')` |
| "open kinetik", "open kinetikcircle" | `openProduct('kinetik')` |
| "open hq" | `openProduct('hq')` |
| "open landing" | `openProduct('landing')` |
| "open arganta", "open argantalab" | `openProduct('arganta')` |
| "stop listening", "cancel" | disarm the mic |

`openProduct` opens the same `ProductDetail` popup as clicking a product
card — same overview/desktop/mobile inspector, same gesture swipe/pinch
behavior once it's open.

Table lives in `intents.ts` as data, not a big switch — adding a phrase is a
one-line addition.

## SFX (v1.1)

Synthesized with the Web Audio API (`copilot/sfx.ts`) — no audio files, no
CDN, matching the zero-asset style of the Music/Video Builder engines
elsewhere in HQ:

- **Listen chime** (two-note ascending) — plays the instant the mic arms.
- **Close chime** (two-note descending) — plays on disarm, but only if the
  mic was actually armed (never fires from unmount/cleanup teardown).
- **Confirm tick** (short high blip) — plays every time a spoken phrase
  matches an intent, independent of which intent it was.

## Guardrails (the part that makes this bulletproof, not a demo)

**Voice — `SpeechRecognition`:**
1. Continuous recognition **silently ends** every ~60s or on any pause.
   `onend` must auto-restart while an `armed` ref is true, or the mic goes
   dead after a minute with no visible error.
2. `no-speech` and `aborted` errors are routine, not fatal — swallow them;
   only surface `not-allowed` (permission denied) to the user.
3. Feature-detect (`window.SpeechRecognition ||
   window.webkitSpeechRecognition`); if absent, hide any voice-only affordance
   and no-op. No Firefox support — do not throw.
4. Requires a secure context (HTTPS or localhost).
5. Stop recognition on `visibilitychange` (tab hidden) and restart on
   return, matching the existing `useLandingPulse` pattern
   ([Landing.tsx:95](../apps/hq/src/surfaces/Landing.tsx)).
6. One recognizer instance for the page lifetime; toggling the mic
   button starts/stops it, never constructs a second one.

**Gesture — MediaPipe `HandLandmarker`:**
1. Model + WASM **must** be self-hosted under `apps/hq/public/mediapipe/`.
   Do not point `wasmLoaderPath` / `modelAssetPath` at Google's CDN — this
   repo has an offline launch config (`hq-offline`) and the CDN fetch
   silently breaks it.
2. Camera is a **heavier permission ask than mic** — gate behind an
   explicit, separate, off-by-default toggle. Never auto-start on page load.
3. Throttle the detection loop to ~15 fps (don't run every rAF tick at
   display refresh rate — wastes GPU for no gain on swipe detection).
4. On toggle-off or unmount: `track.stop()` every `MediaStreamTrack`,
   `landmarker.close()`. Verify the camera indicator light actually turns
   off — this is the single most common leak in webcam features.
5. Pause on `visibilitychange`, same as voice.
6. Debounce swipe firing (~700ms cooldown) so one physical swipe doesn't
   fire multiple product-cycle events.
7. Mirror the video feed (selfie view) so a swipe left reads as left.
8. Off entirely under `prefers-reduced-motion` — no camera-driven UI churn
   for users who opted out of motion.
9. Pinch and swipe are mutually exclusive per frame — while a pinch is
   detected, swipe history is cleared so a closing hand can't also register
   as a swipe. Pinch has its own ~900ms cooldown, separate from swipe's.

**Both:**
9. Feature-unsupported → hide the affordance, never throw. This must not be
   able to crash Landing on any browser.
10. `intents.ts` has no DOM/browser API — pure functions, easily unit-tested.
    `apps/hq` has no test runner configured today, so this ships
    test-ready rather than test-covered; the adapters are thin and
    disposable, the intent table is not.

## Non-goals (explicit, to prevent scope creep back in)

- No LLM / conversational voice. Fixed phrase table only.
- No gesture control of orb explosion, rotation, or camera.
- Only swipe (cycle) and pinch (close) gestures — no additional gesture
  vocabulary (fist, point, thumbs-up, etc.) unless explicitly requested.
- No cross-browser polyfill for Firefox's missing `SpeechRecognition`.
