CIRCLE HQ — LAYER-3 ORCHESTRATION SPEC

The promotion of Circle HQ from a dashboard you query into a router that acts. Design rule inherited from the vault: the router is a RAIL, not a reasoner — a deterministic protocol any model (Fable today, Opus/Sonnet tomorrow) executes identically. Consistency lives in this structure; the model choice only sets raw capability.

00 · POSITION

Where this sits, and the one founding decision

Layer 3 of the stack: L0 context readable → L1 memory unified (graph + vault) → L2 skills laddered → L3 router → L4 connectors as reach.

Founding decision: the router is a protocol before it is a service. Phase 0 is a checklist executed in-session with zero new infrastructure. Automation (Supabase log, write-path, scheduled runs) is earned by the manual loop running enough times to calibrate the effort-scorer. Building the service first would automate uncalibrated judgment.

Everything below is traceable to the live graph pull of July 7 (RECON.md), the handoff docs, or the vault skeleton — flagged #inferred where it isn't.

01 · THE LOOP

Nine steps, every request, no exceptions

1 INTAKEState the request + deliverable in one line. Classify domain.
2 LADDERBind to a graph node BEFORE work. No node → _INBOX or reject.
3 SCOREeffort-scorer: A/H/S/C/V → model + scaffolding + escalate-if.
4 ROUTEOffice path → which skills load, which connectors allowed, which gates apply.
5 LOADContext pack: node_get, relevant vault files, the skill(s). Bounded; compact if over.
6 REACHConnectors only from the path's allowlist, underneath the router.
7 RUNExecute. Reversible → proceed. Irreversible → stop-and-flag gate.
8 VERIFYAdversarial pass sized by stakes score. Proof = graph movement or acceptance criteria met.
9 HARVESTWrite back: vault summary, verdict on the node, run-log row.
No orphan actions. Step 2 extends the graph's "no orphan opinions" rule from verdicts to work itself. A task that ladders to nothing is either a genuinely new idea (capture in _INBOX/capture.md, ladder later) or busywork (decline). External/reservoir work is the one exception: it ladders to the vault (50-PROFESSIONAL), not the graph.
RETAIN guard. Nodes under a RETAIN verdict don't spawn work — the router may only route protection (regression checks) at them, never "improvements". 41 of the 76 open verdicts are RETAIN; without this guard the router drifts into polishing what works.

03 · SCORING & ESCALATION

The scorer is the personality; escalation is observable

Step 3 uses new-skills/effort-scorer.md (thresholds DRAFT — uncalibrated until ~20 logged runs). The router adds three hard escalation triggers that override any score:

  • Frame-guessing: the executing model is inventing the frame rather than filling one → one tier up. This is the ambiguity ceiling; scaffolding can't buy it.
  • Two failed verifies on the same task → one tier up or human. Never three attempts at the same tier.
  • Stakes=2 with verification=2 → top tier or human, regardless of total.
Every scoring — hit or miss — is a run-log row. The Guild path reviews the log weekly: which task types were over-provisioned (Fable effort on captions) or under-provisioned (Sonnet guessing at frames). That review is what turns draft thresholds into calibrated ones.

06 · ADVERSARIAL PASS ON THIS SPEC

What a skeptic should poke at

  • Seed-graph risk propagates: if the Bridge serves seed data, the router would ladder real work to fictional state. Confirming the endpoint is P0-blocking for graph-laddered runs.
  • The loop has 9 steps and one user. Real risk it's too heavy for small tasks — mitigation: score total ≤3 collapses steps 4–6 into defaults (one-line log row still required). If even that gets skipped in practice, the protocol has failed the usability test and should shrink, not be enforced harder.
  • Ownership/execution split is #inferred — reasoned from the handoff's "media → builder path", not from anything Aldyth said explicitly. Cheap to change; decide at P0.
  • Nothing here is validated: zero loops have run. This spec earns trust the same way signals do — by its provenance moving from placeholder (today) to live (20 logged runs).
