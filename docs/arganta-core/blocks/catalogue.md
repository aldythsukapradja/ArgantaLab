## Slots + empty state, per block

Data-bearing blocks ship `data-empty` in their markup and render a built-in
empty state until the generator removes it and fills the slots. Structural/
presentational blocks (nav, hero, footer, pricing, testimonials, form-modal,
feature-grid, calendar) ship sensible generic default content instead — not
"data" in the fake-numbers sense the empty-state rule guards against.

## Theming + assembly-safety

Full contract: `docs/arganta-core/blocks/README.md` and
`docs/arganta-core/B4a-Block-Design.md` §1–4. Short version: seven
`--brand-*` variables mirroring `makeBrand()`, every color derived via
`color-mix()`, every selector scoped `.blk-<id>`, one IIFE per block with a
`data-wired` idempotency guard, zero external requests.

## Chart data-seam gotcha (worth remembering)

`chart-line`/`chart-bar`/`chart-donut` read their `<script type="application/json"
data-fill="…">` content ONCE, inside their own IIFE, at parse time — same as
real B2 output, where the generator bakes the real JSON into the HTML string
before the browser ever sees it. A tool that fills chart slots via DOM
mutation AFTER the page has already loaded (as `preview.html`'s harness
initially did) will find the chart already rendered its empty state and
never re-renders, since the IIFE already ran and guarded itself with
`data-wired`. `preview.html` works around this by filling JSON seams in the
raw HTML STRING before it's ever parsed — see its `preFillJsonSeams()`. Any
other tool touching these blocks (the B2 generator, a future Builder
`insert_component`) must fill JSON data BEFORE first render, not after.
