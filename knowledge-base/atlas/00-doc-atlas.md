> Every markdown doc in the repo, read and **cross-checked against the actual source**, then given a verdict: did it ship, ship *partially*, get superseded, or never get built? Source docs are left where they are — this is the standardized *view* over them. Paths are shown as `code`, not links, so this file stays portable inside Obsidian.

## LashiraBloom — working docs

> [!note] Arc
> This cluster is the "it actually shipped" half of LashiraBloom: a grand Stardew-clone buildplan that converged, in ~two weeks, into a live farm + tiered combat + circle PvP game on a 60x48 castle-center map (later generalized into realms: arena/bloomwall/festival/keep/kitchen), plus a matching set of HQ operator "Builder" surfaces that publish tuning and audio into the shared @arganta/combat and @arganta/audio packages. The striking pattern: almost every doc stamped "CONCEPT, no build" was built within days — four separate Battle Builder redesigns (plan → visual → v2 IA → forge feel) collapsed into one shipped BattleBuilder.tsx that merged all of them (Overview/Combat/Bestiary/Rewards + a Monster Lab), and three music docs became a full waveform/spectrogram/generative Music Builder. The real dead-ends are the over-ambitious substrate that never fully landed: the MMORPG architecture's four-tier server-adjudication authority stayed victim-authoritative, registry-as-DATA ("add a monster from HQ without a deploy") was flagged as the load-bearing gap in every audit and never shipped, and the ElevenLabs provider was never wired. The cluster's scar tissue is the PvP debugging saga — a five-round, same-day marathon chasing "shows Hit but victim stays full," resolved only by reading Kingdom's flat-HP implementation and finding the zone-crossing HP-refill/faint-heal bug.
